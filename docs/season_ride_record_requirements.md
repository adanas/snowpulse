# シーズンライド記録機能 要件定義書（確定版）

## 1. 概要
ユーザーが1シーズン（10月1日〜翌年5月31日）を通じて積み上げたライディング実績を確認できる「シーズンライド記録画面（専用画面）」を提供します。
過去のシーズン実績の振り返りや、制覇ゲレンデリスト・最多訪問ゲレンデ（ホームゲレンデ）の可視化により、継続的なライディングへのモチベーションを高めます。

---

## 2. 確定仕様・機能一覧

### 2.1 シーズン期間の定義と判定ロジック
* **シーズン対象期間**: **毎年 10月1日 00:00:00 〜 翌年 5月31日 23:59:59**
* **シーズン表記**: `YYYY-(YY+1) Season`（例: `2025-26 Season`, `2026-27 Season`）
* **判定ロジック**:
  * 10月1日〜12月31日の走行: 開始年が当年のシーズン（例: 2026/10/04 ➔ `2026-27 Season`）
  * 1月1日〜5月31日の走行: 終了年が当年のシーズン（例: 2026/01/17 ➔ `2025-26 Season`）
  * オフシーズン（6月1日〜9月30日）: 直近終了したシーズンを初期選択。

### 2.2 必須記録・集計項目（コアメトリクス）
| 項目 | 単位 | 集計ロジック |
| :--- | :--- | :--- |
| **総ライド距離** | km | 対象シーズン内の全チェックアウト済みセッションの `totalDistanceMeters` 合計 |
| **獲得標高** | m | 対象シーズン内の全チェックアウト済みセッションの `totalElevationDropMeters` 合計 |
| **チェックイン回数** | 回 (Days) | 対象シーズン内の完了セッション数（滑走日数） |
| **最高速度** | km/h | 対象シーズン内の全セッション・全ランを通じた最高速度（`maxSpeedKmh` の最大値） |

### 2.3 採用機能（ユーザー指定）
1. **記録（訪問スポット一覧）リスト**
   * シーズン内にチェックインしたユニークなスキー場数（例: `記録 (5)`）
   * スキー場ごとの訪問回数一覧リスト（例: 川場スキー場 6回, 野沢温泉 4回, 丸沼高原 2回...）
   * **HOME（最多訪問ゲレンデ）バッジ**: 最もチェックイン回数が多いスキー場のカード内に「🏆 HOME」バッジをコンパクトに表示。
2. **総ライド本数（Total Runs）**
   * 対象シーズン内の全ラン数合計（例: `76 Runs`）
3. **過去シーズン切り替え（Season Selector）**
   * ドロップダウン選択式で過去シーズン（`2026-27`, `2025-26`, `2024-25` 等）を切り替え可能。
   * シーズンを切り替えると、全メトリクス・訪問ゲレンデ一覧・グラフが即座に連動更新。

## 3. UI/UX 画面設計（案B: 専用画面型）

### 3.1 画面導線
* **ダッシュボード画面（ヘッダー上部）**: 雪山ヘッダーの右上に「📅 シーズン記録」アイコンボタン（またはトロフィーアイコン）を配置し、タップで専用画面へスムーズに遷移。
* **戻るボタン**: 専用画面左上の「←」でダッシュボードへ戻る。

### 3.2 画面レイアウト構成（専用画面）
1. **ヘッダーエリア**:
   * タイトル: 「シーズンライド記録」
   * **シーズンセレクター（ドロップダウン）**: `[ 2026-27 Season ▼ ]`
2. **SEASON RIDE SUMMARY ヒーローカード（グラスモーフィズム 2.0）**:
   * 右上の重複表示（「滑走日数」）は撤廃し、クリーンなヘッダーに統一。
   * 総ライド距離（Neon Cyan, 例: `142.8 km`）
   * 最高速度（Amber, 例: `68.2 km/h`）
   * 獲得標高（White, 例: `18,450 m`）
   * チェックイン回数（Emerald, 例: `14 回`）
   * 総ライド本数（Purple, 例: `76 Runs`）
3. **記録 セクション**:
   * ヘッダー: 「記録 (5)」
   * 各スキー場カード:
     * スキー場名
     * 「🏆 HOME」バッジ（最多訪問スポットに付与、レイアウト崩れを防ぐコンパクト設計）
     * チェックイン回数
     * 総ライド距離・最高速度
4. **シーズン総括 シェアボタン**:
   * 「シーズンライド実績を共有」ボタン（SNSカード生成導線）

## 5. データ設計・実装アプローチ

### データベースクエリ（Android Room）
既存の `SessionDao` に以下のクエリを追加、または `startTime` の期間フィルターで抽出：
```sql
SELECT * FROM sessions 
WHERE startTime >= :seasonStartMs AND startTime <= :seasonEndMs 
  AND endTime IS NOT NULL
ORDER BY startTime DESC
```

### 集計ロジック
```kotlin
data class SeasonStats(
    val seasonName: String,          // 例: "2026-27"
    val totalDistanceMeters: Float,  // 総距離
    val totalElevationDropMeters: Float, // 獲得標高
    val totalCheckIns: Int,          // チェックイン回数
    val maxSpeedKmh: Float,          // 最高速度
    val totalRunsCount: Int,         // 総ライド本数
    val visitedResorts: List<Pair<String, Int>> // スキー場名と訪問回数
)
```
